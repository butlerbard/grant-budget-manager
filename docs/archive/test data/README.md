# 匯入測試資料

請先將專案設定為執行中，執行期間建議設為 **2026/01/01 至 2026/12/31**，專案經費總額 **3,000,000 元**。CSV 欄位採系統匯入頁範本，UTF-8 BOM 編碼。預算與對應核銷／流用資料都包含「補助款」和「自籌款」。

## 正常情境

依序匯入 `正常情境/01_預算明細.csv`、`正常情境/02_核銷紀錄.csv`、`正常情境/03_經費流用.csv`。預算 80 筆、8 個單位各 10 科目，總額 3,000,000 元，並同時使用補助款與自籌款；核銷 301 筆，單位及專案總核銷均低於上限，包含待核銷、零元及多付款對象分配。流用 120 筆且金額不全相同；每筆流出及流入都對應預算檔中相同經費類別、經費屬性及預算科目的明細，流出金額也未超過匯入當下的明細可用餘額。指定的 40,000 元流用會使專案彙總的「講座鐘點費」流用後預算低於核銷金額，呈現科目超支。

## 匯入拒絕情境

每個檔案都是單獨測例，一次只匯入一個：
- `01_預算超過專案總額.csv`：在總額 3,000,000 元的空白專案測試，預算合計 3,000,001 元。
- `02_核銷超過單位上限.csv`、`03_核銷找不到匹配預算明細.csv`、`04_登錄日期超出專案期間.csv`：先匯入正常預算，再分別測試；使用尚無核銷的測試專案。
- `05_流用超過科目可用餘額.csv`、`06_流用缺少經費屬性.csv`：先匯入正常預算及正常核銷，再分別測試；不要先匯入正常流用。超額流用測例使用自籌款明細並在該筆一次流出時超過核銷後餘額；缺屬性測例也使用自籌款。

測例需分別使用隔離的測試專案，勿把拒絕測例與正常資料混在同一批匯入。所有資料皆為假資料。
